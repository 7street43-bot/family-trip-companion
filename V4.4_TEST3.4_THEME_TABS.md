# V4.4 TEST3.4｜Explore Theme Tabs

Runtime: `4.4.0-test3.4`
Base: V4.4 TEST3.3 one-click certified build

## Scope

This release keeps the four primary entity types unchanged and adds a visually subordinate custom-topic layer.

### Primary tabs

- 景點 / 住宿 / 餐廳 / 其他 remain the only primary entity types.
- All four stay on one row on mobile.
- Each tab now has a compact icon tile, stronger selected state and count treatment.
- No entityType migration or DB schema change.

### 我的主題

A smaller second-level row appears below the four primary tabs.

Users can create up to 20 custom themes using either:

1. **手動收藏** — explicitly choose saved entities.
2. **條件自動收納** — combine verified conditions:
   - 室內
   - 適合目前年齡
   - 最愛
   - 還沒去
   - 帶娃輕鬆
   - comma-separated keyword OR matching

Themes are stored in IndexedDB `settings.exploreThemes`, so existing JSON snapshot export/import inherits them without a new database store or schema version.

## Filtering semantics

Custom themes are a second-level filter, not a new data type.

Example: a theme may contain an attraction, restaurant and hotel. While `景點` is selected, only attraction members show; switching to `餐廳` keeps the same theme and shows restaurant members. This preserves the primary type hierarchy while allowing cross-type thematic collections.

Unknown information is not guessed:

- `室內` requires confirmed indoor metadata.
- `適合目前年齡` uses the existing structured age gate.
- `帶娃輕鬆` requires enough known friction inputs and score >= the existing “輕鬆” threshold.

## QA integration

The deployed one-click acceptance lab adds:

`自訂主題資料／篩選防呆`

It verifies manual membership, smart rules, type × theme intersection and JSON-serializable settings without mutating user collections or itineraries.
